# Privacy boundary

## Pilot notice

Agent Signal is an opt-in, experimental service operated by Luke Ivers. The initial reporting API runs on Cloudflare Workers and D1 on the Free plan. It accepts fixed error categories, ordering numbers and a rotating random reporter capability. Application storage keeps a hash of that capability and minimal observation/budget records; it discards extra request fields. Do not submit logs, repository URLs, names, account identifiers or other private details.

Reports affect ten-minute counts, but the ordering records live longer to prevent old retries from reopening reports. Cleanup is scheduled every five minutes. Cloudflare may separately retain network/security metadata and database recovery history; D1 Free has seven days of Time Travel history. Using MCP can also put the capability in your agent transcript. We cannot promise end-to-end anonymity or erasure from every provider system.

Counts are unverified observations and may be forged or duplicated. No reports does not establish health. Hosting limits or an incident can make the service unavailable. There is no uptime or support-response guarantee. Reporting can be disabled if security, abuse, cost or maintenance concerns arise. Use the repository's security-reporting instructions for concerns; never post private diagnostics in public issues.

## Technical boundaries

Application storage contains only exact cohort categories, SHA-256 random-capability pseudonyms, sequence, state, server timestamps, prior-failure flag, and bounded budget counters. It stores no account/repository identifiers, raw outputs, names, emails, IPs, headers, command text, or free-text reports. Unexpected request fields are projected away before database calls. Invalid requests and exceptions have fixed responses and are not logged by application code. Worker observability defaults off in the generated build.

The local hook sees tool output in memory to classify a narrow GitHub HTTPS server error. Its request contains only enums/sequence plus bearer Authorization. Local state uses a hash of the session ID for the filename, a random rotating token, increasing sequence, and HMAC hashes of repository destinations to match recovery. It never saves those original identifiers/output. Files are 0600 in a 0700 directory. Local state remains sensitive and stays on the user's machine; delete the state directory on uninstall. No state is uploaded. Network requests refuse redirects and time out.

Ten-minute count expiry differs from deletion. Watermarks must remain until the capability expires, at most 24 hours after the encoded issue hour. The core cleanup physically deletes expired records; a scheduled handler exists, but **Sites scheduling and a maximum physical-deletion delay have not been verified**. No 24-hour physical-erasure claim is made. Budget metadata can remain up to two additional days until cleanup. A future retention claim must include actual cleanup cadence.

Host access logs, tracing, request URLs/headers, MCP tool arguments, edge/security logs, and D1 backups/Time Travel are separate boundaries. Application projection cannot erase what the hosting ingress already received. A caller could put private details into a URL before rejection. Providers may retain network metadata/backups independently, even after live rows are deleted. Disclose provider-retained metadata and unverified policies before a consented pilot; do not claim that application projection guarantees end-to-end erasure. Do not promise end-to-end absence of PII today.

[Sites documentation](https://learn.chatgpt.com/docs/sites) describes automatic unique-visitor and page-view analytics. We have not verified how visitors are distinguished, analytics retention, or an opt-out. Disabling application Worker observability does not establish that host analytics or ingress logs are disabled. Cloudflare documents D1 Time Travel as always on, with [7-day free-plan or 30-day paid-plan history](https://developers.cloudflare.com/d1/reference/time-travel/); the actual Sites-managed policy remains unverified. Deletion of a live row does not establish deletion of its backup history.

Scheduled cleanup remains active when reporting is disabled, provided the host invokes the handler and supplies the database. Neither stopping ingestion nor ten-minute count expiry proves physical deletion. A pilot can disclose an unverified physical deletion deadline; it cannot claim a proven deadline. The direct Cloudflare configuration schedules cleanup every five minutes. On 2026-10-07 an expired synthetic observation/budget pair was observed deleted while an unexpired pair remained. Hosted verification evidence is recorded in [verification](verification.md); a single observed run does not establish a guaranteed maximum deletion delay.

Anonymous access deliberately provides no device fingerprinting or account linkage. Rotating tokens reduce linkage but do not prevent forged reporters or Sybil attacks. Shared egress may itself explain correlated failures. Counts establish reported symptom scope, not independent failures, provider fault, geographic breadth, or a confirmed outage.

MCP mutation capabilities are tool arguments and can therefore appear in the client/model transcript and tool logs. This is a broader disclosure scope than the local REST hook. Prefer the local adapter if this scope is unacceptable. For an opted-in manual MCP session, use `node clients/codex/new-capability.mjs /absolute/private/token-file` to generate a fresh0600 file without printing it; rotate within22 hours, reset sequences on rotation, and never use an account-derived value. Allow the agent to read that file only after consenting to model-visible capability use. The capability is a pseudonymous bearer mutation credential, never an account credential.

The stable gateway constructs a new upstream REST request after validation. It forwards only enums/sequence, the rotating reporter capability, Content-Type, and the Sites service credential. It does not forward client cookies, IP headers, MCP IDs/metadata, unexpected arguments or private rehearsal headers. Extra upstream response fields are also discarded. Sites and Cloudflare still receive their own network metadata at ingress; this protection does not remove provider logs/backups. This is a retained migration adapter, not the launch reporting path. The approved direct Cloudflare deployment removes the Sites credential and origin; the owner-private Sites prototype is separate. See [hosting](cloudflare-cutover.md).
